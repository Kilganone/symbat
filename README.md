# SIMB-AD — рекламная платформа для онлайн-аптек (MVP)

Три интерфейса в одном приложении: **онлайн-аптека**, **кабинет рекламодателя** (фарм-бренда) и **кабинет аптеки**. Все аптеки, бренды и данные вымышленные и демонстрационные. Рецептурные препараты не рекламируются.

## Запуск

Нужен **Node.js 18+**. Без `npm install`, внешних пакетов и API-ключей.

```bash
npm start
```

Откройте http://localhost:3000 (другой порт: `PORT=8080 npm start`).

Данные хранятся в `data/db.json` и сохраняются после перезапуска. Кнопка «Сбросить демо-данные» в подвале (или `POST /api/reset`) возвращает исходное состояние. Для первого запуска создаётся детерминированная история за 6 дней: события, а не случайные числа.

## Главный сценарий демонстрации

1. **Кабинет рекламодателя** → «Новая кампания»: товар, бюджет, CPC, ключевые слова, скидка, аптеки. Score показывает «Недостаточно данных».
2. **Онлайн-аптека** → поиск по ключевому слову кампании (например, «витамин»). Вверху выдачи появляется блок с пометкой «Реклама».
3. Нажмите на рекламный товар (это оплачиваемый клик), выберите аптеку, добавьте в корзину и нажмите «Забронировать».
4. В корзине нажмите «Подтвердить демо-продажу» (то же можно сделать в «Кабинете аптеки»).
5. **Кабинет рекламодателя**: растут показы, клики, расходы, брони, продажи, выручка и ROAS; пересчитывается SIMB Score с вкладом каждой компоненты.
6. **Кабинет аптеки**: рекламный доход (70%), клики, заказы с рекламы и распределение по аптекам.

## Как считается

**Ad Rank** = 0,5·Relevance + 0,3·Bid + 0,2·Discount. Все компоненты в диапазоне 0–1:
- Relevance: совпадение слов запроса с ключевыми словами кампании (1 при точном совпадении) либо с названием, брендом и категорией товара (с коэффициентом 0,8). В поиске показываются только кампании с Relevance ≥ 0,5.
- Bid = min(1, CPC / 300 ₸).
- Discount = min(1, скидка / 30%).

Показываются только активные кампании с остатком бюджета и товаром в наличии в выбранных аптеках. В поиске показываются до двух объявлений. Блок «Рекламные скидки» ранжируется тем же Ad Rank.

**SIMB Effectiveness Score** = 0,15·N(CTR) + 0,30·N(CVR) + 0,40·N(ROAS) + 0,15·N(New Buyer Rate), где N(X) = min(100, факт / цель × 100). Цели: CTR 6%, CVR 15%, ROAS 5, доля новых покупателей 60%. Это гипотеза MVP, а не отраслевой бенчмарк. Без показов или кликов вместо Score выводится сообщение о нехватке данных. Если кликов меньше 20, оценка помечается как предварительная.

**Деньги и атрибуция** (всё считается из журнала событий `impression → click → reservation → sale`):
- Списание только за валидный клик по CPC. Один показ даёт максимум один оплаченный клик, повторный клик по тому же показу не списывает деньги. Клик должен быть сделан в течение 30 минут после показа, из той же сессии, по активной кампании с достаточным бюджетом.
- Бронь засчитывается рекламе, если она создана в течение 24 часов после клика, в той же сессии, на тот же товар. Один клик атрибутирует не больше одной покупки. Скидка кампании применяется к такому заказу в аптеках кампании.
- Выручка и ROAS считаются только по подтверждённым демо-продажам (бронь без подтверждения в них не входит). Повторное подтверждение не создаёт новую продажу. Отмена брони возвращает остаток.
- Новый покупатель: по телефону, нет предыдущих продаж этого бренда.
- Рекламный доход делится 70% аптеке и 30% SIMB-AD по фактически оплаченным кликам каждой аптеки. Клик относится к аптеке, в которой показано объявление.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/pharmacies` | Аптеки |
| GET | `/api/products?q=&category=` | Товары: поиск, минимальная цена, наличие |
| GET | `/api/products/:id` | Цены и остатки по аптекам |
| POST | `/api/ads/serve` | Реклама для запроса и фиксация показов (`query`, `sessionId`) |
| POST | `/api/ads/click` | Оплачиваемый клик (`impressionId`, `sessionId`) |
| POST | `/api/cart/quote` | Расчёт корзины с учётом рекламной скидки |
| POST | `/api/reservations` | Бронирование (`customer`, `items`) |
| GET | `/api/reservations?pharmacyId=` | Брони |
| POST | `/api/reservations/:id/confirm` | Подтвердить демо-продажу |
| POST | `/api/reservations/:id/cancel` | Отменить бронь |
| GET / POST | `/api/campaigns` | Список и создание кампаний |
| PATCH | `/api/campaigns/:id` | Включить или выключить (`{"active": true}`) |
| GET | `/api/analytics/advertiser?campaignId=` | KPI, Score, графики, кампании |
| GET | `/api/analytics/pharmacy/:id` | Показатели аптеки и распределение дохода |
| POST | `/api/reset` | Сбросить демо-данные |

## Ограничения MVP

Нет авторизации, платежей, антифрода и интеграций с маркетплейсами; реклама привязана к сессии браузера. Показатели нельзя использовать как доказательство прироста продаж (для этого нужен A/B-тест) или для медицинских рекомендаций.
